# 실험 결과 읽기

실행 후 터미널이나 웹 화면에 표시된 `output` 경로를 엽니다. 파일은 실습 호스트의 `outputs/`에 저장됩니다. 브라우저의 **저장된 결과 보기**에서도 영상과 JSON을 열 수 있습니다.

모델의 완료 응답, 제어기의 동작 종료, 실제 작업 성공을 함께 확인하세요.

| 기록 | 의미 |
|---|---|
| `goal_complete` 또는 모델의 성공 보고 | 모델이 관찰한 장면을 바탕으로 내린 판단 |
| `completed`, `sequence_completed` | 제어기가 동작 순서를 끝낸 상태 |
| `task_success`, `physical_task_success` | 물체 위치·로봇 상태 등으로 계산한 작업 평가 |

<a id="blocks"></a>
## 이미지 비교·블록 조작

- 이미지 비교: `outputs/01_model_comparison/<실행_ID>/`에서 입력 이미지, 모델별 `response.json`, `overlay.png`를 비교합니다. 좌표 파싱 오류가 있으면 응답 원문을 먼저 확인합니다.
- 블록 조작: `outputs/02_isaac_sim/<실행_ID>/metrics.json`의 `placement_within_tolerance`와 `final.png`를 확인합니다. 이 값은 목표 위치에 대한 배치 평가이며, 지시한 색의 블록을 옮겼는지는 이미지로 확인합니다.
- 모델 지시: `outputs/02_isaac_sim_agent/<실행_ID>/`에서 판단별 입력과 도구 호출을 확인하고, 응답에 표시된 동작 폴더의 영상·평가값과 대조합니다.
- 방해 후 재관찰: `outputs/03_perturbation_recovery/<실행_ID>/summary.json`의 `baseline`과 `perturbed`를 비교합니다. `recovery_observed`는 방해 발생, 첫 행동의 배치 실패, 이후 배치 성공, 최종 트레이 내부 위치를 함께 검사합니다.

<a id="streaming"></a>
## Live 감지·중단·복구

결과 폴더는 `outputs/04_streaming_recovery/<실행_ID>/`입니다.

| 파일·항목 | 확인할 내용 |
|---|---|
| `evaluation.json`의 `interrupted_while_action_active` | 첫 행동이 진행 중일 때 중단했는지 |
| `evaluation.json`의 `streaming_recovery_observed` | 변화 감지·중단 이후 배치에 성공했는지 |
| `sent_frames/`, `turn_XX/` | 전송한 이미지와 시각, 모델 응답, 복구 도구 호출 |
| `presentation/synchronized.mp4` | 동작·API 입력·응답을 시간순으로 비교 |
| `validation.json` | `validate_recording.py`로 생성한 영상·시각 검사 결과 |

S2 목적지 이동에서는 관찰 자세로 돌아오며 그리퍼가 열릴 수 있습니다. `validation.json`의 `interpretation.red_already_inside_before_recovery_action`이 참이면 복구 호출 전에 블록이 이미 트레이 안에 있던 경우입니다.

S3 낙하에서는 그리퍼 개방 요청과 실제 낙하를 구분합니다. `evaluation.json`의 `physical_drop_confirmed`와 영상을 확인하세요. 감지 지연은 교란 시점부터 모델 보고를 호스트가 받은 시점까지이며, 프레임 전송·API 처리·네트워크 지연을 포함합니다.

<a id="scenarios"></a>
## Franka 서랍·Spot 순찰

결과 폴더는 각각 `outputs/05_drawer/<실행_ID>/`, `outputs/06_patrol/<실행_ID>/`입니다. 두 실험 모두 `evaluation.json`을 확인합니다.

| 실험 | 주요 평가 항목 |
|---|---|
| 서랍 열기 | `opening_threshold_met`, `motion_quality_passed`, `task_success` |
| 닫힘 후 재열기 | `effective_closure`, `closed_before_recovery_action`, `reopened_after_recovery_action`, `recovery_success` |
| Spot 도착·표시등 판독 | `arrived`, `fell`, `indicator_correct`, `task_success` |
| 통로 차단 후 우회 | `barrier_injected`, `local_obstacle_stop`, `rerouted_after_barrier`, `recovery_success` |

서랍은 개방량뿐 아니라 다른 서랍·문의 움직임, 팔 속도, 파지 접촉, 그리퍼 해제, 종료 후 안정화도 평가합니다. `materials/motion_quality.png`와 `motion_quality.csv`에서 세부 값을 확인할 수 있습니다.

`--smoke`는 API 없이 제어기를 점검하는 실행입니다. 모델의 도구 선택이나 Spot 표시등 판독 결과는 포함하지 않습니다.

<a id="cooperative"></a>
## 두 Franka 협업·자재 운송

결과 폴더는 `outputs/07_cooperative/<장면>/<조건>/<실행_ID>/`입니다. 결과 자료 생성 후 `summary.json`과 `model_report.json`을 비교합니다.

- 두 Franka: 양쪽 트레이에 빨강·파랑 블록이 각각 한 개씩 있어야 합니다. `summary.json`의 `final_ground_truth.satisfied_requirements`는 충족한 배치 요구사항 수이고 `physical_task_success`는 최종 작업 성공 여부입니다.
- 자재 운송: 적재 → 자재를 싣고 출발 → B 도착 → 하역의 진행 이력과 최종 자재 위치를 확인합니다.
- `api/`, `model_timeline.json`은 모델 판단, `jobs.csv`는 로봇별 작업, `truth.jsonl`은 평가용 물리 상태입니다.
- 여러 실행을 비교할 때는 `outputs/07_cooperative/results.csv`를 사용합니다.

### 별도 영상 진행률 평가

`coop_progress.py`를 실행하면 `video_progress/midpoint/`와 `video_progress/final/`에 영상 입력·응답·평가가 저장됩니다.

각 `evaluation.json`에서 `bracket_matches`는 진행률 구간, `completion_presence_matches`는 완료 여부, `completion_absolute_error_seconds`는 완료 시각 오차를 나타냅니다. `80–100%` 구간과 작업 완료는 별개입니다. 응답 상태가 `incomplete`이면 [실행방법 6.11절](../실행방법.md#coop-results)의 재호출 절차를 사용하세요.

## 영상과 로그 비교

통합 영상의 `API OUTPUT`에는 모델 호출·보고와 제어기의 반환값인 `tool_result`가 함께 표시됩니다. 긴 응답은 일부만 표시되므로 전체 내용은 JSON·텍스트 로그에서 확인합니다. 카메라 원본 영상과 통합 영상은 시간축이 달라 재생 길이가 다를 수 있습니다.

[입력·출력과 하위 제어의 연결](폐루프_구성과_모델_제어기_역할.md#video)에서 화면 표시와 제어 단계의 의미를 확인할 수 있습니다.
