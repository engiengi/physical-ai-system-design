120 Hz 물리 스텝마다 최대 속도와 비대상 관절 변위를 집계했습니다. 팔 최대 관절 속도는 약 **0.70002 rad/s**, 두 번째 서랍 최대 이동량은 **7.9×10⁻¹¹ m**, 다른 문 최대 각도는 **2.7×10⁻⁸ rad**로 비대상 움직임은 수치 오차 수준입니다. 두 열기 모두 양쪽 손가락–손잡이 접촉을 확인했고, 최종 그리퍼 개방과 마지막 1.5초 안정화 기준을 통과했습니다. 접촉 중 미세한 속도 변화는 그래프에 남아 있습니다. 이 검사로 모든 충돌의 부재나 실물 로봇 안전성을 보증하지 않습니다.

하위 제어는 **NVIDIA RMPFlow + 이 장면에 보정된 Cartesian 동작 단계**입니다. 기존 학습 서랍 정책을 교체했습니다. 관절 목표 변화율을 제한하고 gain을 일정하게 유지하며, 재시도 때 초기 관절 위치로 강제 복귀하지 않습니다. 위 서랍은 `stiffness=0`, `damping=10`의 수동 서랍이며 다른 서랍과 문은 잠그지 않았습니다. 손잡이를 물체에 고정하는 부착 트릭 없이 물리 접촉으로 당깁니다. 범용 학습 정책의 성능 개선으로 설명하지 않습니다.

카메라는 서랍장 앞의 고정 사선 RGB입니다. 하위 제어는 시뮬레이터의 관절·손잡이 위치를 사용하고, ER 2는 RGB와 도구 종료 상태로 다음 행동을 결정합니다. 닫힘 주입은 외부 개입을 단순화한 관절 위치 변경입니다. 사람의 손으로 미는 접촉은 구현하지 않았습니다.

저수준 이동은 공식 Spot 평지 보행 정책입니다. 자기 위치는 시뮬레이터에서 얻고, 경유점 그래프는 미리 정의했습니다. ER 2는 두 경로 중 다음 행동을 선택하고 표시등을 판독합니다. 빠른 충돌 방지는 로컬 제어기가 처리합니다. 새로운 지도의 SLAM·범용 자율 주행·모델의 연속 관절 제어로 해석하지 않습니다.

입력 카메라는 로봇 위치·진행 방향을 따라가는 전방 RGB 카메라입니다. 실제 Spot의 전체 센서 구성을 재현하지 않았습니다. 단색 사각 표시등과 단순 실내 공간을 사용했습니다.

핵심 결론은 **“서로 다른 환경에서도 영상 관찰 → 행동 도구 선택 → 새 관찰에 따른 재판단을 연결할 수 있다”**입니다. 제어기의 실패·안전 정지·모델의 완료 오판도 함께 보여줍니다. 모델 하나가 센서 처리부터 전체 관절 제어까지 수행했다고 설명하지 않습니다.

새 서랍 실행의 출력 형식에서는 불필요한 `indicator_color`를 제거했습니다. 이전 서랍 기록의 해당 필드는 평가에 사용하지 않습니다. 표시등 판독 결과는 Spot 실험에서만 해석합니다.

두 대표 실행의 MP4·전송 JPEG·타임스탬프 검사를 통과했습니다. 새 환경의 Spark 모니터 직접 GUI와 웹 화면도 확인했습니다. 원격 WebRTC 전송 자체는 기존 블록 환경에서 검증했으며, 이번 두 환경을 원격 클라이언트로 별도 수신하는 검사는 반복하지 않았습니다.

## 5. 이전 실패·사전 점검

| 실행 | 분류·해석 |
|---|---|

초기 Spot 사전 점검의 `task_success=false`는 색상 보고까지 요구하는 공통 평가기에서 나온 값입니다. 이 파일은 원본 그대로 보존합니다. 이후 `--smoke` 실행은 과제 전체 성공을 `null`로 기록하고, 도착·개방량·도구 종료 상태로 제어기를 점검합니다.

Spot 대표 실행의 `state.json/injected`는 당시 호스트의 서랍 주입 플래그였으므로 `false`로 남아 있습니다. 실제 Spot 장애물 삽입은 `events/`의 `barrier_inserted`와 `evaluation.json/barrier_injected=true`로 확인합니다. 현재 코드는 두 환경의 이벤트를 함께 읽어 이 필드를 기록하도록 보완했습니다.
