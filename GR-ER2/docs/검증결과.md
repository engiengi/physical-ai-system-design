## 평가와 데이터의 의미

- `controller_status: completed`는 제어 시퀀스 종료입니다.
- `placement_within_tolerance`는 기하·속도·그리퍼 조건 검사입니다.
- `instruction_success`는 자동 판정하지 않습니다. 색상·대상·사용자 지시는 이미지와 함께 확인합니다.
- 평가용 물체 정답 좌표는 모델에게 제공하지 않습니다.
- 모델은 단계별 RGB 한 장을 받습니다. 전체 MP4는 사용자 관찰·원고용 기록입니다.

- 임의 물체·다른 크기·복잡한 장애물에 대한 파지는 검증 범위에 포함하지 않습니다.

## Live 카메라 스트리밍 감독·복구 — 2026-09-21

최종 검증 실행: `outputs/04_streaming_recovery/20260921_125851_1a4b63dc/`

일반 ER 2가 첫 집기 행동을 계획하고, 별도의 `gemini-robotics-er-2-streaming-preview` Live API 세션이 동작 중 카메라를 감독했습니다. JPEG를 1.1초 이상의 간격으로 전송하고, 앞선 턴이 완료된 뒤 heartbeat 텍스트를 전달했습니다. 모델에 방해 시점이나 정답 이동 좌표는 알리지 않았습니다. 실제 물리 복구 도구는 `BLOCKING`으로 실행했습니다.

| 항목 | 실제 확인 결과 |
|---|---|
| 전송 | 지속 WebSocket 세션, 실제 카메라 JPEG 39장 |
| 판단 | 기준 장면 확인 → 변화 없음 → 목표 이동 감지 → 복구 행동 → 완료 확인, 총 5개 턴 |
| 방해 후 감지 지연 | 약 5.85초, 호스트 수신 시각 기준 |
| 첫 행동 중단 | `interrupted_by_stream_monitor`, 행동 시작 후 5.6초(시뮬레이션 시간)에 종료 |
| 중단 후 처리 | 현재 관절 목표 유지 → 2초 관찰 자세 복귀, 물체 초기화 없음 |
| 복구 | 같은 Live 세션이 새 좌표로 집기·배치. 목적지 XY 오차 약 19.6 mm |
| 마지막 판단 | Live 모델 `goal_complete`, 평가·최종 이미지에서도 트레이 배치 확인 |
| 종합 판정 | `streaming_recovery_observed: true` |
| 전체 영상 | 39.3초 / 393프레임 / 10 FPS, 실제 경과 약 51.2초 |

복구 중 파란 블록도 약 2.7 cm 이동했습니다. 목표 복구와 충돌 없는 조작은 별개로 검토해야 합니다. 손목 카메라나 60 Hz 모델 제어는 이번 실험이 아닙니다. 일반 ER 2와 Live 모델이 함께 사용됐으므로 기존 6.4절 대비 성능 향상을 정량 주장할 수 없습니다.
