# Franka–Spot–Franka 자재 운송 실험

실행은 [실행방법 6.10절](../실행방법.md#transport), 실측 결과는 [협업 실험결과](협업_실험결과.md)를 확인합니다.

## 목표와 세 조건

컨베이어 A의 자재 하나를 A 팔 → Spot 등 적재함 → B 팔 순서로 전달해 컨베이어 B에 놓습니다. 로봇 세 대의 작업에는 선후 조건이 있습니다. 개별 모터 동작의 종료와 물체 인계의 성공을 구분합니다.

| 조건 | 환경의 개입 | 기대하는 ER 2 판단 |
|---|---|---|
| 정상 | 없음 | 적재 확인 → 운반 → 도착·화물 확인 → 하역 확인 |
| 적재 실패 | A의 첫 집기에서 손가락을 열린 상태로 유지 | 빈 적재함·남아 있는 자재 확인 → 출발 보류 → 다시 집기 |
| 통로 장애 | Spot 출발 후 직선 통로에 충돌체 삽입 | 안전 정지 응답·전방 영상 확인 → 우회 선택 → 인계 재개 |

조건은 호스트가 설정합니다. 모델 프롬프트에는 이번 조건명·교란 발생 시점·실제 자재 위치를 넣지 않습니다. 실패 가능성과 사용 가능한 경로는 작업 지침으로 알려 줍니다. 복구가 항상 성공한다고 가정하지 않습니다.

## 모델 입력·출력과 하위 제어

1. 모델 입력: 작업 지시, 작업장 A/B·Spot 전방·적재함 카메라 관측, 직전 최대 6초 영상, 공개 작업 응답과 호출 이력.
2. 모델 출력: `observe`, `start_action`, `get_job_status`, `cancel_job`, `report_progress`, `finish_task` 호출 및 설명.
3. 팔 명령: 로봇 ID와 관측 ID, 이미지상의 정규화된 집기·배치 점. 집기 지점 주변 25×25 픽셀의 깊이에서 돌출된 윗면 중심을 보정하고, RGB-D 역투영과 알려진 자재 크기로 3D 목표를 정합니다. 전체 장면에서 물체 정답을 찾지 않으며, 해당 국소 영역에서 윗면을 구분하지 못하면 명령을 거부합니다. 원래 지점·보정 지점은 `events.jsonl`의 `depth_point_refinement`로 남깁니다.
4. Spot 명령: 도착 작업장 A/B와 `direct`/`detour` 경로. 실제 보행은 공식 Spot 정책, 경유점 추종과 자기 위치 기반 제어가 담당합니다.
5. 안전 인터록: 팔 인계 중 Spot 이동, Spot 이동 중 팔 인계를 제한합니다. 도착 위치·자세는 하위 제어가 확인합니다. 자재 적재 성공은 이 인터록이 보증하지 않습니다.
6. 모델이 다음 판단을 기다리는 동안에도 물리와 카메라 녹화는 진행됩니다. 일반 Interactions API의 이미지·과거 영상 방식입니다.

중앙 ER 2 한 개가 세 로봇의 도구를 호출합니다. A 적재·Spot 운송·B 하역이라는 역할과 도킹 지도는 사전에 제공합니다. 모델이 맡는 것은 관측을 근거로 한 호출 시점, 인계 확인, 재시도와 경로 선택입니다. 작업 의존성 때문에 로봇 동작은 순차적으로 진행합니다.

전체 화면은 시청자에게만 보여 줍니다. `coop_run.py`는 운송 모델에 `overview` 관측을 보내지 않고 요청도 거부합니다. 별도의 사후 영상 진행률 실험은 전체 영상을 사용하므로 입력 조건이 다릅니다.

## 물리 구현과 단순화

- 5cm, 0.05kg 동적 자재와 두 Franka, 공식 Spot 보행 정책을 사용합니다.
- 적재함은 Spot 몸체의 고정된 충돌 형상입니다. 별도 유연 구조나 실제 적재함의 하중 정격을 검증하지 않습니다.
- 자재는 초기화 이후 이동·고정하지 않습니다. 집기·적재·운반·하역은 충돌·마찰·중력으로 이루어집니다.
- 컨베이어는 인계 위치에서 정지한 지지대입니다. 벨트 구동·움직이는 자재 추적 파지·B 도착 후 추가 벨트 이송은 범위에 포함하지 않습니다.
- Spot 전방 카메라는 위치/yaw를 따르는 안정화 가상 카메라, 적재함 카메라는 위에서 내려다보는 가상 추적 카메라입니다. 실제 센서 장착 설계나 카메라 마스트의 물리를 재현하지 않습니다.
- 하위 제어에 알려진 지도, 자기 위치, 깊이와 관절 상태가 있습니다. 모델에 평가 정답을 전달하지 않는다는 점과, 시스템 전체가 ground-truth-free라는 주장은 구분해야 합니다.
- Spot은 경유점 방향으로 몸체를 회전한 뒤 전진하고, 인계 지점에서는 팔이 접근할 수 있는 방향으로 정렬합니다. 저속 전방·측방 혼합 명령에서 정체가 발생해 개발 중 회전·전진 방식으로 보완했습니다.

## 평가와 원고용 자료

각 조건의 원본 카메라, API에 실제 넣은 이미지·영상, 응답 원문, 도구 이력, 물리 평가를 함께 저장합니다. 통합 영상의 로컬 제어 단계 표시는 모델 출력과 분리합니다.

진행률은 적재 / 자재를 싣고 출발 / 자재와 함께 B에 도착 / B에 하역의 네 이력 조건으로 정의합니다. 최종 성공은 B 도착 이력과 마지막 자재 위치를 대조합니다. 모델이 성공이라고 답해도 실제 상태와 다르면 완료 오판으로 기록합니다.

별도 영상 평가의 완료 시각은 자재가 B 지지면에 있고, 그리퍼가 열린 채 연속 프레임에서 안정된 최초 시점입니다. 하위 제어가 팔을 초기 위치로 복귀시키는 시각은 `reference_controller_cycle_complete_seconds`로 따로 기록합니다. 전체 실시간 작업 성공 플래그는 이 복귀까지 확인하므로 두 시각에는 차이가 있습니다.

`transport_smoke.py`는 정확한 시뮬레이터 좌표를 쓰는 **API 없는 제어 진단**입니다. 이 결과를 ER 2가 좌표를 추론한 결과로 소개하지 않습니다. 모델 실험의 실제 판단은 `api/`와 `model_timeline.json`에서 확인합니다. 소수 조건별 사례로 일반 성공률을 주장하지 않습니다.
