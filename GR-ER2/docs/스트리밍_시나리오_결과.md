위 지연은 **교란 명령 시점부터 모델 보고를 호스트가 받은 시점까지**이며, JPEG 전송 간격·API 처리·네트워크 지연을 포함합니다. 고정 상부 카메라에서 최대 1 FPS로 입력하고, 저수준 관절 제어는 Franka 제어기가 담당합니다.

이 영상은 원본 프레임과 타임스탬프로 만든 **실제 경과 시간 1배속 동기화 재생본**입니다. 화면의 API 이미지는 가장 최근 전송한 프레임이며, 표시된 응답은 도착한 뒤부터 나타납니다. 모델이 내부적으로 어느 픽셀에 주목했는지는 알 수 없습니다. `API OUTPUT` 칸에는 모델 호출·보고와 로컬 제어기의 반환값(`tool_result`)이 함께 표시되므로 구분해서 읽습니다. [입출력·제어 단계 설명](폐루프_구성과_모델_제어기_역할.md#video)에 정확한 의미를 정리했습니다.

## 2. 정확하게 해석할 부분

### S1: 대상 이동 감지와 재파지

- 빨간 블록을 집기 전에 위치를 바꿨습니다. 모델이 새 위치를 보고 중단·재파지했습니다.
- 최종 요청 배치점 XY 오차 약 **14.5 mm**입니다.
- 복구 과정에서 파란 블록도 약 **17.5 mm** 움직였습니다. 충돌 없는 조작을 검증한 결과로 사용하지 않습니다.

### S2: 목적지 변화 감지와 재계획

- 빈 트레이를 X 방향 -18 cm 이동했습니다. 모델은 원래 중심 `[473,306]`과 새 중심 약 `[675,308]`을 비교해 `goal_moved`를 보고했습니다. 좌표 순서는 `[y,x]`입니다.
- **중단 후 관찰 자세로 돌아오는 과정에서 그리퍼가 열렸고, 재계획 호출 직전에는 블록이 이미 옮겨진 트레이 안에 놓여 있었습니다.** 복구 행동의 `before.red=[0.395,0.213,0.035]`, `tray_center=[0.31,0.235]`와 영상에서 확인됩니다.
- 이후 모델은 같은 트레이 안에서 다시 집어 새 좌표로 배치했습니다. 최종 요청 배치점 오차 약 **7.3 mm**입니다.
- 원고에서는 **“이동한 목적지를 감지하고 좌표를 수정했다”**고 설명합니다. 이 사례만으로 재계획이 없었으면 반드시 실패했을 것이라고 말할 수 없습니다.

### S3: 실제 낙하와 좌표 수정 후 복구

- 실제 접촉으로 블록을 들어 올린 후 높이 12 cm에서 개방 명령을 적용했습니다. 약 **0.23초** 뒤 블록 높이가 6 cm 아래로 떨어졌고, 그리퍼 양쪽 관절은 각각 약 4 cm 열린 상태였습니다. 테이블로의 낙하는 물리 계산 결과이며 물체 위치를 순간이동하지 않았습니다.

## 3. 원본 자료와 실행

위 세 실행 폴더에는 공통으로 다음을 보관합니다.

- `input_video/camera.mp4`: 전체 상부 카메라 원본 영상.
- `rollout_video/side.mp4`: 전체 측면 카메라 원본 영상.
- `presentation/`: 통합 MP4와 주요 시점 PNG. 실제 경과 시간 기준이므로 원본 영상과 길이가 다릅니다.
- `sent_frames/`: 실제 전송 JPEG와 전송 시각.
- `initial_actor/`, `turn_XX/`, `live_config.json`: 초기 일반 ER 2 계획, Live 요청·응답·도구 호출 원문.
- `api_timeline.jsonl`, `frame_timestamps.jsonl`: 합성 영상의 시간 정렬 근거.
- `evaluation.json`, `initial_metrics.json`, `recovery_metrics.json`, `events/`: 교란·실행·배치 평가.
- `validation.json`: 프레임 수·비디오 정보·전송 간격 검사와 복구 전 목적지 도달 여부 점검.
- S3의 `evaluation_trace.jsonl`: 물체·그리퍼의 실제 상태 추적. 평가에만 사용하며 API로 전달하지 않습니다.

다시 실행하려면 [실행방법 6.6절](../실행방법.md#stream-scenarios)의 명령 또는 웹 화면 시나리오 선택을 사용합니다. 종료는 같은 문서의 9절입니다.

## 4. 연구 근거와 적용 범위

[QT-Opt 공식 설명](https://research.google/blog/scalable-deep-reinforcement-learning-for-robotic-manipulation/)에는 이동한 대상에 대한 대응과 사람이 그리퍼에서 물체를 떨어뜨렸을 때 다시 집는 사례가 있습니다. S1·S3은 이 교란 유형을 현재 Franka·블록 장면에 맞췄습니다.

[Inner Monologue 공식 프로젝트](https://innermonologue.github.io/)는 실패 피드백과 작업 중 바뀌는 목표에 따른 재계획을 다룹니다. S2는 이 문제 설정을 목적지 트레이 이동으로 단순화했습니다. 원 논문의 실험 장면과 같은 구성이라는 뜻은 아닙니다.

여기서는 ER 2의 시각 보고를 호스트가 정해진 상태 전이로 연결합니다. **기준 관찰 → 감독 → 변화 보고 시 중단 → 관찰 자세 복귀 → 모델의 복구 좌표 생성 → 결과 확인** 순서입니다. 복구 상태로 전환하는 제어 흐름은 작성된 코드이며, 좌표와 관찰 보고는 실제 모델 출력입니다. 논문의 정책 학습·벤치마크·성공률을 재현하거나 자율적인 일반 복구 능력을 정량 입증한 실험은 포함하지 않습니다.
